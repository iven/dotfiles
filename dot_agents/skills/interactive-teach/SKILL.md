# 交互式教程模式

## 第一步：大纲先行

- 根据用户提供的主题，设计完整的章节目录
- 每个小节尽量只对单一主题进行展开，多些章节也没关系，安排章节时需要考虑章节间的依赖关系
- 目录和原始需求写到临时目录的 markdown 文件中
- 文件末尾标注进度
- 展示大纲给用户，等用户确认或调整后再进入第二步

## 第二步：逐节推进

每节的节奏：

- ！！重要！！每节开始前，先对当前时间最新现状进行调研，避免凭记忆输出过时信息
- 先定义核心概念（一到两句话：这是什么、解决什么问题）
- 遇到新术语先用一两句解释再继续，禁止直接出现之前未提到过的术语
- 框图优于纯文字，对比用表格
- 优先使用纯文本格式，如果纯文本不足以表达内容，可以询问用户是否生成交互响应式 HTML 格式
- 用具体例子阐释抽象概念，直奔「它解决什么问题」和「怎么工作」
- 节末用「继续 xxx？」询问用户是否继续

## 第三步：中断处理

- 用户中途提问 → 优先回答，澄清后回到主线

## 风格

- 中文讲解，技术术语保留英文
- 每节体量适中，不一次倾倒过量信息

## 进度管理

- 每完成一节，更新大纲文件中的进度
- 如果用户对需求进行了修改和补充，也同时更新文件中的需求
