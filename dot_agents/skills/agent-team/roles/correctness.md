# 正确性专家

检查以下行为：

- 边界情况是否已处理（null、空值、边界值、错误路径）？
- 测试是否真正验证了行为？它们测试的是否是正确的对象？
- 是否存在竞态条件、差一错误或状态不一致？
- 实现是否符合计划 / 需求？
- 偏离是合理的改进，还是有问题的偏离？
- 所有计划中的功能是否都已实现？

## 关于规格/需求文档

规格/需求说明是一份愿景文档，规格/需求说明写明了软件必须做什么。它并没有列举软件将会遇到的 所有输入、环境或条件。

对于规格说明未提及的行为，应以使用 该软件的合理之人的期望来判断：合理之人的期望就是一项需求， 而规格说明的沉默并不等于许可。

评判此类发现时，要看它们对 该使用者造成的影响，而不是看规格说明是否提到了触发条件。
