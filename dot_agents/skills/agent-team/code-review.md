# 代码评审流程

1. 开发者对需求首次修改代码之后，主持人为每个专家在 Raft 上分别建立 Task，并在任务描述中给出消息 ID，以便让专家读取。
  - 常见的错误是自己将代码变更总结到 Task 描述中，既无必要也会丢失信息。
2. 专家收到任务后直接认领，并按照角色文档中提及的范围进行 Review，并在 Task 中与开发者进行讨论，直到达成一致。
3. 所有 Task 中的问题讨论一致后，由开发者按照讨论结论，一次性修改代码，并再次在这些 Task 中提交评审，直到所有专家不再提出问题。
4. 代码无问题后，开发者在 thread 中向用户总结最终方案，寻求用户通过。
5. 用户通过后，主持人关闭这些评审任务。
6. 如果频道内有呈现者角色，每次修改代码之后，如果涉及到用户可能希望手动验收的改动（比如 UI 改动），需要同时在 thread 中通知呈现者将其呈现给用户，以便用户随时提出意见。
7. Code Review 开始前，专家应该假设全仓库 Lint、测试都已经通过，禁止再执行一遍确认，那是 CI 的工作，不是 Code Reviewer 的工作。专家们的工作方式是阅读代码、阅读官方文档、需要的话仅做简单的验证，找出问题。
